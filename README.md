# Ещё один этаж

Первая версия портретной 2D-игры на C# для Android с совместимой с iOS игровой логикой. Без платных ассетов, рекламы и внешних сервисов. Оформление — авторская 2D-графика в тёплой палитре: восемь вариантов соседей, дом в разрезе с окнами, растениями, крышей и шахтой лифта, металлическая кабина со стеклянными раздвижными дверями. Все PNG включены в проект и не требуют покупки или скачивания ассетов.

![Авторские персонажи и элементы оформления — набор графики, не скриншот запуска](Docs/ArtPreview.png)

## Что изменилось в оформлении

- Люди с лицами, волосами, разным цветом кожи и одеждой. Различия только косметические: правила у всех одинаковые.
- Номер нужного этажа находится в пузыре над головой. Под ногами ожидающего — полоса терпения; в кабине полоса скрывается, номер сохраняется.
- Один и тот же персонаж перемещается из очереди в лифт. Есть плавное появление, покачивание при ходьбе, исчезновение при уходе и надпись «Спасибо!» после доставки.
- Дом в разрезе: шесть коридоров, окна с занавесками, картины, светильники, растения, крыша, фундамент и дальний городской фон. Нажимать можно как на номер этажа, так и на сам коридор.
- Лифт с направляющими, подсветкой, табло, раздвижными стеклянными дверями и плавным разгоном/торможением. Через стекло видны люди и их цели.
- Главное меню с кнопкой «Как играть? Обучение». Перед первой сменой предлагается пройти или пропустить обучение из четырёх страниц: цифры и терпение, управление, очки и множитель, рост сложности. Обучение можно повторить из меню. На HUD видны прогресс серии, множитель, заполненность и потери. Полный лифт подсвечивается.
- Шестерёнка в главном меню и игровом HUD открывает настройки. В настройках — переключатель звука с сохранением выбора. Выключение немедленно останавливает уже звучащий сигнал. Из партии настройки открываются через паузу; закрытие возвращает на паузу, а не запускает игру автоматически. Разные негромкие сигналы посадки, доставки, ухода и нажатия сохранены.
- Портретная игровая область центрируется даже в широком Game View; safe area учитывается отдельно.

Это доработанное оформление прототипа. Публикация для потребителя всё ещё требует проверки Play Mode/устройств, баланса и требований магазинов.

## Открытие и запуск

1. Версия проекта — **Unity 6.6, точно 6000.6.7f1**, как в установленном у пользователя редакторе. Unity Hub и активная лицензия Unity по-прежнему нужны. Скачайте полный архив репозитория и распакуйте его в новую папку.
2. Для Android установите модуль **Android Build Support**, включая **Android SDK & NDK Tools** и **OpenJDK**.
3. На Windows дважды нажмите **OPEN_GAME.cmd** рядом с папками Assets, Packages, ProjectSettings. Команда ищет Unity 6000.6.7f1 в стандартной папке Hub и открывает проект напрямую через `-projectPath`, без добавления в список Hub. Также автоматически проверяет путь пользователя `D:\6000.6.7f1\Editor\Unity.exe`. При другой установке предложит указать полный путь к `Unity.exe`. Лог записывается в `Unity-open.log`. Запускать нужно из распакованной папки. Альтернатива: Hub → Add → Add project from disk. Основной файл PlayerSettings включён в проект; Unity создаст остальные стандартные настройки и импортирует встроенный пакет Unity UI. Причина предыдущего отказа Hub на компьютере пользователя по одному сообщению не установлена; смена версии сама по себе не доказывает исправление этого отказа.
4. Включён **Input Manager (Old)** (`activeInputHandler: 0` в PlayerSettings). Если открываете игру внутри другого проекта, в **Edit → Project Settings → Player → Other Settings → Active Input Handling** выберите **Input Manager (Old)** либо **Both**. Если Unity потребует перезапуск, согласитесь. Используется стандартный `StandaloneInputModule`, поддерживающий мышь и касания, пакет Input System не нужен.
5. При первом открытии сцена создаётся автоматически, если игровая сцена отсутствует и редактор открыт на пустой неизменённой сцене. Если этого не произошло, выполните **Ещё один этаж → Создать или открыть игровую сцену**. Команда создаст `Assets/OneMoreFloor/Scenes/Game.unity`, настройки `GameSettings.asset`, камеру, EventSystem и корневой GameApp, добавит сцену в список сборки. Существующая сцена по этому пути только открывается, существующие настройки сохраняются. Несохранённую текущую сцену редактор предложит сохранить.
6. Нажмите **Play**, затем **Начать смену**. Дополнительных ручных привязок компонентов нет. В Game View выберите портретный размер, например 540×960.

UI создаётся при запуске. В меню отображаются рекорд, кнопка обучения и шестерёнка настроек; короткие процедурные сигналы не требуют аудиофайлов. Перед первой сменой можно пройти обучение или сразу начать игру. Пока открыто обучение, игровая сессия не запущена: пассажиры не появляются и очки не меняются. Новая версия обучения предлагается также тем, кто уже видел старую короткую подсказку. На телефоне и в редакторе нажимайте номера этажей слева. Активная поездка завершается целиком; последнее нажатие во время движения задаёт следующую остановку. Можно повторно выбрать текущий этаж для посадки новых пассажиров. Автоматического подбора всех появившихся на стоянке пассажиров нет: посадка выполняется по команде остановки.

## Правила и настройки

Шесть этажей, четыре места, поражение после трёх уходов. Очередь FIFO. На полной остановке сначала выходят пассажиры, затем заходят ожидающие; внутри терпение заморожено. Начальный этаж — первый. Счёт за доставку — 10 × множитель; первые пять доставок дают ×1, следующие пять ×2, затем ×3. Уход сбрасывает серию. Посадка не влияет на серию.

Выберите `GameSettings.asset` в Project и изменяйте поля `Rules` до запуска:

| Поле | Начальное значение | Назначение |
|---|---:|---|
| Seconds Per Floor | 1.25 | Время движения на один этаж |
| Stop Seconds | 0.65 | Минимальная остановка после обслуживания |
| Patience Seconds | 32 | Терпение ожидающего |
| Initial Spawn Seconds | 5 | Интервал появления в начале |
| Minimum Spawn Seconds | 1.5 | Нижняя граница интервала |
| Difficulty Score Cap | 450 | Очки, при которых достигнут предел сложности |
| Starting Floors | 3 | Нижние этажи, на которых появляются первые пассажиры |
| Starting Route Distance | 1 | Максимальная разница этажей маршрута в начале |
| Delivery Points | 10 | Базовые очки |

Первый пассажир появляется через 1.5 секунды. Сложность зависит только от набранных очков, а не от времени. Начальный интервал 5 секунд плавно уменьшается до 1.5 секунды при 450 очках и далее не сокращается. Ожидание без доставок не повышает сложность. Уход сбрасывает серию, но не очки и не достигнутую сложность. Новая партия начинается с начальной сложности. Поле RampSeconds прежней версии больше не используется.

При стандартном балансе пассажиры сначала появляются только на этажах 1–3 и едут на соседний этаж. Четвёртый этаж включается при 150 очках, пятый при 300, шестой при 450. Максимальная длина маршрута тоже постепенно увеличивается от одного до пяти этажей. Верхние тихие коридоры приглушены и отмечены «ПОЗЖЕ»; все кнопки лифта остаются доступны. При росте уровня появляется сообщение, текущий уровень и активные этажи видны под заголовком.

 Начальный баланс ориентирован на 2–4 минуты, но длительность зависит от решений игрока и требует реального плейтеста. В ходе партии настройки менять не следует. Поля Floors/Capacity/LossLimit тоже доступны, но первая версия рассчитана и оформлена под 6/4/3. Ожидающие показаны в один ряд до пяти человек, затем в два ряда с уплотнением. При экстремальных настройках и большой очереди люди и подписи станут мелкими; для таких режимов потребуется отдельная компоновка.

Пауза останавливает движение, генерацию и терпение; потеря фокуса и сворачивание автоматически показывают паузу. Возобновление — явной кнопкой. Рекорд и настройка звука сохраняются локально через PlayerPrefs. Перезапуск создаёт новую сессию. Safe area пересчитывается при изменении размеров и учитывает вырезы экрана. Очки, заполненность, потери, текущая и следующая цель показаны над зданием; посадка, доставка и уход сопровождаются сообщением и звуком.

## Android: тестовая сборка

1. Создайте сцену указанной командой. **File → Build Profiles → Android → Switch Platform**; проверьте, что Game включена в Scene List (если используете собственный список профиля, добавьте сцену туда).
2. В Player Settings задайте свой уникальный **Package Name** вместо `com.independentstudio.onemorefloor`, версию и код версии. Ориентация — Portrait. Минимальный API по генератору — 26; Target API — установленный актуальный SDK. Требования Google Play к Target API перепроверьте непосредственно перед публикацией.
3. Для будущего релиза выберите **IL2CPP**, архитектуру **ARM64**. Для локального теста включите **Development Build**, отключите **Build App Bundle**, выполните **Build** в `Builds/Android/OneMoreFloor.apk`. Для устройства включите USB debugging, используйте **Build And Run** или `adb install -r Builds/Android/OneMoreFloor.apk`.
4. Для Google Play позднее понадобятся AAB, собственная подпись (keystore храните вне Git), значок, политика конфиденциальности, проверка требований магазина и тестирование устройств. Эта версия не заявляется готовой к публикации.

iOS: логика не содержит Android API. Сборка требует модуля iOS, macOS, Xcode и подписи Apple; в этом окружении не выполнялась.

## Архитектура и проверки

- `Core/DifficultyCurve.cs`: ограниченная кривая сложности по очкам: частота появления, активные этажи и максимальная длина маршрута.
- `Core/GameModel.cs`: независимые от Unity `Elevator`, `PassengerQueues`, `PassengerSpawner`, `GameSession`, `GameRules`. Все изменения игрового времени проходят через Tick; обработка небольшими шагами фиксирует порядок событий. При кадре длиннее 250 мс время ограничивается, чтобы после зависания не возникал шквал уходов.
- `Runtime/GameSettings.cs`: ScriptableObject с балансом.
- `Runtime/GameApp.cs`: экраны, HUD, ввод, обучение, пауза, звук и локальное сохранение.
- `Runtime/GameUI.cs`: единая палитра, создание UI и загрузка собственных спрайтов.
- `Runtime/BuildingView.cs`: дом, подсветка этажей, кабина, двери и размещение пассажиров.
- `Runtime/PassengerView.cs`: человек, номер над головой, терпение, переход из очереди в кабину и уход.
- `Resources/Art`: 19 готовых PNG; `Editor/ArtImporter.cs` задаёт импорт спрайтов, сглаживание и границы растягиваемых панелей.
- `Tools/generate_art.py`: исходный генератор собственной графики (для изменения графики нужен Pillow, для запуска игры — нет).
- `Editor/SceneSetup.cs`: безопасное создание сцены и первичных мобильных настроек.
- `Editor/FirstOpenSetup.cs`: создание сцены после первого импорта; существующие и изменённые сцены сохраняются без изменений.
- `OPEN_GAME.cmd`: открытие распакованного проекта в установленном Windows-редакторе 6000.6.7f1, включая путь с пробелами.
- `Tests/Program.cs`: исполняемые проверки ядра без Unity и сторонних библиотек.

При установленном .NET SDK 8: `dotnet run --project Tests/LogicTests.csproj` из корня. Проверяются вместимость, FIFO, терпение внутри, полная остановка, высадка перед посадкой, смена следующей цели, повторные нажатия, пауза/возобновление, конец игры, чистый перезапуск, множитель и предел генерации.

Unity Editor, Windows и Android SDK в среде реализации отсутствуют: запуск OPEN_GAME.cmd, автоматическая подготовка сцены, импорт проекта, компиляция Unity-части, Play Mode, реальная safe area/касания/звук и APK здесь **не проверены**. После открытия обязательно проверьте Console, старт сцены, несколько партий, паузу при сворачивании, перезапуск, пропорции 9:16 и 9:20, переполненную очередь и установку APK на устройство. Результаты независимых тестов записаны в `Tests/RESULTS.md`.


## Обновление с первой версии

Проще всего закрыть Unity, распаковать свежий архив в новую папку и открыть её через OPEN_GAME.cmd. Путь `D:\6000.6.7f1\Editor\Unity.exe` теперь проверяется автоматически. Сцену и баланс инструмент создаст при первом импорте; если не создал — используйте меню «Ещё один этаж».

Если уже меняли сцену или баланс, сначала сохраните копию старого проекта: вместо замены всего проекта можно перенести только папку `Assets/OneMoreFloor/Runtime` и новую `Assets/OneMoreFloor/Resources` вместе с их `.meta`, а также всю папку `Editor` с `.meta` (включая `TypographySetup`, `FirstOpenSetup` и `SceneSetup`). Существующие Game.unity и GameSettings.asset заменять не нужно. Новое оформление строится при следующем Play. После копирования дождитесь компиляции.

Дополнительные проверки из корня: `dotnet run --project Tests/SourceChecks/SourceChecks.csproj` проверяет синтаксис C# 9 (не ссылки на Unity API); `python Tools/check_art.py` декодирует PNG, проверяет метаданные импорта и уникальность GUID (нужен Pillow). Для визуального регресса в Unity проверьте меню, обучение, пустой/полный лифт, пять человек в очереди и очередь больше пяти, выбранный следующий этаж, доставку, уход, паузу и повторную партию. В портретных 9:16/9:20 и широком Game View цифры должны оставаться над головами, двери — не выходить за шахту, а пассажиры — ехать вместе с кабиной.


## Проверка настроек, обучения и сложности в Unity

1. В меню откройте шестерёнку, выключите звук, закройте настройки, снова откройте: положение переключателя сохраняется. После полного перезапуска звук должен остаться выключенным. Включите его обратно.
2. Из меню откройте обучение, пройдите четыре страницы, вернитесь назад, завершите его. Затем начните смену: очки и потери должны быть нулевыми. Возможность повторить обучение остаётся в меню.
3. Во время движения откройте шестерёнку: движение, терпение и генерация останавливаются. Закройте настройки: остаётся экран паузы. Только «Продолжить» возобновляет партию. Повторите со сворачиванием приложения при открытых настройках.
4. Набирайте очки: интервал появления уменьшается, затем появляются маршруты на верхних этажах. Отдельно проверьте 149/150, 299/300 и 449/450 очков. После 450 очков частота и дальность больше не растут. Уход не уменьшает достигнутую сложность; повторная партия её сбрасывает.
5. У кабины теперь более прямые пропорции, стальная рама, панели стен, поручень, потолочный свет, пол с перспективой, пульт и тонкие стеклянные двери. Люди и их номера должны быть видны через стекло как на стоянке, так и в движении. Для главного меню предусмотрен отдельный вертикальный рисунок кабины, чтобы её не растягивать.

Эти шаги требуют Unity/устройства и в облачной среде не выполнялись.


## Чёткость текста и изображений

Интерфейс переведён с Unity UI Text на **TextMesh Pro / SDF** (входит в используемый `com.unity.ugui` в Unity 6). В проект включены DejaVu Sans и DejaVu Sans Bold с кириллицей; лицензия лежит рядом с TTF. SDF-плашки над головами имеют собственный размер 24–32 × 23–28 единиц Canvas вместо высоты в 15–18 единиц и не уменьшают цифры до минимума автоматически. Рисунки пересозданы в двойном разрешении, включая персонажей 328×480. Для рисунков включены mipmaps и trilinear-фильтрация при уменьшении; панели и значки сохраняют bilinear без mipmaps. Сжатие текстур на Windows, Android и iOS отключено, масштаб панелей сохранён через PPU=200 и соответствующие границы nine-slice. Canvas использует pixel-perfect координаты.

При первом открытии `Editor/TypographySetup.cs` автоматически импортирует **TMP Essential Resources** из уже установленного пакета Unity, если они ещё не импортированы, затем создаёт обычный и жирный SDF-атласы. Для этого не нужен новый пакет или сетевой запрос. Кириллица, цифры и используемые символы предварительно добавляются в атласы. Материалы и текстуры сохраняются как подресурсы font assets, чтобы шейдер и атласы попадали в сборку. Генерируемые SDF assets не хранятся в Git: их создаёт редактор из включённых TTF.

Дождитесь сообщения «SDF-шрифты с кириллицей готовы» перед Play. Если появилось штатное окно TMP Importer — нажмите **Import TMP Essentials**, дождитесь импорта. Если подготовка не выполнилась, используйте **Ещё один этаж → Подготовить качественный текст**, затем создайте/откройте сцену обычной командой. Защита Play Mode и проверки перед сборкой предотвращают запуск без подготовленных шрифтов. Существующие сцены и баланс подготовка не заменяет.

В Game View для проверки:

1. Выберите портретное разрешение **1080×1920** или **720×1280**.
2. Установите **Scale 1x** для оценки пиксельной чёткости (изображение может не помещаться целиком; тогда прокручивайте либо проверяйте в большем окне). На Fit/маленьком масштабе редактор уменьшает уже отрисованный кадр, поэтому оценивать тонкие детали по сильно уменьшенному превью нельзя.
3. Если доступен пункт **Low Resolution Aspect Ratios**, отключите его. Для просмотра всей игры удобно включить **Maximize On Play**.
4. Проверьте цифры у ожидающих, у четырёх пассажиров в кабине, плотную очередь из двух рядов, обычный/жирный текст, увеличение окна и 100%/150% масштаб Windows. В самой сборке эти настройки Game View не действуют.

`python Tools/check_typography.py` с установленным fonttools проверяет реальные таблицы обоих TTF: кириллицу, цифры и все нестандартные символы исходников. SDF-генерация, визуальная чёткость, время первого импорта и расход памяти требуют проверки в Unity/на телефоне; здесь они не измерялись. Изображения и шрифты занимают больше памяти, чем раньше; профиль производительности перед публикацией остаётся обязательным.
